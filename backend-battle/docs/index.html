1. Propósito

Gestiona preguntas de battle (CRUD), salas y jugadores. El esquema PostgreSQL es la fuente de verdad (Flyway crea, JPA valida).

2. Arquitectura (hexagonal)

3. Modelo de datos (esquema exacto)

TablaColumnas / Restricciones
battle_questionsid BIGINT IDENTITY PK · level CHECK(A1..B2) · topic CHECK(daily/travel/work) · prompt · options · correct_index CHECK 0..3 · explanation · UNIQUE(level,topic,prompt)
battle_roomsid UUID PK · code UNIQUE · host_id UUID · level · topic CHECK(mixed/daily/travel/work) · duration_seconds IN(120,180,300) · capacity 2..12 · status CHECK(...) DEFAULT waiting · created_at
battle_playersPK(room_id,user_id) · FK room_id→battle_rooms · alias CHECK len 2..30 · status CHECK(pending/accepted/rejected) · joined_at

Errores { code, message }

400 BAD_REQUEST · 404 RESOURCE_NOT_FOUND · 409 RESOURCE_ALREADY_EXISTS · 500 INTERNAL_ERROR
