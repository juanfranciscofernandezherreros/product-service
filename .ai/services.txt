# Manifiesto de microservicios — un servicio = un repositorio.
#
# Una linea por microservicio, con 5 campos separados por punto y coma (;):
#   SERVICE_NAME;TARGET_DIR;REMOTE_URL;SPEC_FILE;DB_SPEC
#
#   SERVICE_NAME : nombre del microservicio (artifactId, spring.application.name, docs).
#   TARGET_DIR   : carpeta destino DONDE se genera el proyecto (su propio repo git).
#                  Absoluta, o relativa a la raiz del generador. Debe quedar FUERA de este
#                  repositorio (p. ej. ../access-service = carpeta hermana).
#   REMOTE_URL   : repositorio Git remoto propio del servicio (push -u origin main).
#                  Debe existir antes de generar: el script lo comprueba y aborta si no.
#   SPEC_FILE    : ruta (relativa a la raiz) del contrato OpenAPI del servicio. En el modo por
#                  defecto el generador lo deriva del DDL (scripts/generate.py --openapi) y el
#                  campo es informativo. En --mode ai: indicalo para API-First o dejalo VACIO
#                  para que la IA lo derive del esquema en la Fase 0.
#   DB_SPEC      : ruta (relativa a la raiz) del esquema PostgreSQL (DDL) del servicio.
#                  OBLIGATORIO. Lo escribe scripts/split_domains.py desde el export de Supabase.
#
# Ejemplo:
# catalog-service;../catalog-service;https://github.com/tu-usuario/catalog-service.git;specs/openapi/catalog.yaml;specs/domains/catalog.sql
# El puerto de cada servicio es 8081 + su posicion en esta lista.
#
# Las lineas que empiezan por # y las vacias se ignoran.
# Cada servicio se genera en SU carpeta y se sube a SU remoto: NUNCA se combinan en el mismo repo.
# El OpenAPI y el esquema SQL son las especificaciones (fuente de verdad) de cada servicio.
#
