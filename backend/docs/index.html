1. Propósito del servicio

product-service es un microservicio REST que gestiona el ciclo de vida completo (alta, consulta, actualización y baja) de productos de catálogo. Está construido siguiendo arquitectura hexagonal (Ports & Adapters), de modo que la lógica de negocio del dominio permanece aislada de los detalles de infraestructura (REST y persistencia).

2. Reglas de negocio

  • El SKU es obligatorio y debe tener al menos 3 caracteres.
  • El nombre es obligatorio y debe tener al menos 2 caracteres.
  • El precio es obligatorio y debe ser ≥ 0.01.
  • El identificador (UUID) se genera automáticamente al crear el producto.
  • Las invariantes se validan tanto en el dominio como en la capa web (jakarta.validation).

3. Modelo de datos

En persistencia, la entidad JPA ProductJpaEntity se almacena en la tabla products de PostgreSQL y está separada del modelo de dominio Product mediante mappers explícitos.

4. Catálogo de endpoints

Ruta base: /api/v1/products

MétodoRutaDescripciónCódigos HTTP
POST/api/v1/productsCrear producto201 / 400
GET/api/v1/productsListar productos200
GET/api/v1/products/{id}Obtener por ID200 / 404
PUT/api/v1/products/{id}Actualizar producto200 / 400 / 404
DELETE/api/v1/products/{id}Eliminar producto204 / 404

Ejemplos

POST — petición

{
  "sku": "PROD-001",
  "name": "Mechanical Keyboard",
  "price": 99.99
}

201 Created — respuesta

{
  "id": "3f2c9b1a-7e4d-4c2a-9b0e-...",
  "sku": "PROD-001",
  "name": "Mechanical Keyboard",
  "price": 99.99
}

400 Bad Request cuando se incumplen validaciones (ej. sku < 3, name vacío o price < 0.01). 404 Not Found cuando el id no corresponde a ningún producto.

6. Evidencias de calidad

  • JUnit 5 + Mockito: tests unitarios del dominio, del servicio de aplicación y del controlador (@WebMvcTest), cubriendo happy path y errores por endpoint.
  • ArchUnit: reglas que garantizan que domain no depende de application, infrastructure ni Spring.
  • Cucumber BDD: un .feature con escenarios para cada endpoint; reporte HTML en target/cucumber-reports/cucumber.html.
  • Checkstyle: análisis estático sin violaciones.

Verificación completa:

cd backend
./mvnw clean verify
